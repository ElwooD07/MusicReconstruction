# План

Ціль і те, що вже є: `README.md`. Тут лише те, що ще треба зробити.

Порядок: **1** на вихідній машині: відправити проєкт і пісню → **2** на новій машині: отримати проєкт, легке встановлення, зібрати й
перевірити треки → **3** повне встановлення (потрібне лише для A) → **4** шлях B (прототип є), потім A. Проєкт їде через git (`origin`), дані поза git — через `pack-data`.

## 1. Вихідна машина (де є пісня зі стемами)

- [ ] Усе нове (`tools\check_tracks.py`, `scripts\check_tracks.ps1`, `scripts\pack_data.ps1`, `tools\native_*.py`, `scripts\native_*.ps1`,
  новий `ui.py` і `scripts\ui.ps1`, зміни в `setup_all.ps1`, `run.ps1`, `analyze_structure.py`, `requirements-main.txt`, цей план) потрапляє в репозиторій: фіксує й відправляє власник проєкту.
- [ ] Дані, яких у git немає: `run.bat pack-data --dest <флешка> --song <папка пісні> [--weights]`. Папка пісні копіюється
  разом з `orig\` (щоб не розділяти на стеми знову), `gen\` пропускається. `--weights` додає `ace-step\checkpoints` (~14 ГБ),
  щоб не качати їх наново. `env\`, `ace-step\`, `models\`, `temp\` не копіюються: на новій машині вони ставляться скриптом.

## 2. Нова машина: отримати проєкт і зібрати треки

Вимоги до пачки: 12–20 повних пісень (мінімум 8, ≥30 хв), один потрібний стиль, ≥5 треків за 130–155 BPM, стале темпо 4/4,
переважно мінор, живий мікс із чітким кіком/снейром/хетами та гітарами, без публіки, lo-fi й домінуючої електроніки,
mp3 ≥192 кбіт/с або flac/wav, одна папка. Десять треків — нижня частина діапазону для шляху A (ризик перенавчання лишається).

- [ ] Клонувати репозиторій, а наступного разу `git pull`.
- [ ] `run.bat setup-all --check` — що бракує (`MODELS_DIR`, драйвер NVIDIA 570+, місце, Python 3.10–3.12, git). Якщо важкі файли
  мають лежати не в `<проєкт>\models`, задати `setx MODELS_DIR <шлях>` і відкрити новий термінал.
- [ ] `run.bat setup-all --main-only` — лише головне середовище й ваги demucs (~8 ГБ, без ACE-Step): цього досить для наступних кроків.
- [ ] Скласти треки в одну папку (файли прямо в ній, без підпапок).
- [ ] `run.bat check-tracks <папка>`: формат, бітрейт, довжина, BPM, дрейф темпу, тональність + вердикт по всій пачці
  (`tracks_report.json`). Рядки з `!` — підозрілі треки. Метрики лише підказка: тональність і BPM по повному міксу
  бувають хибні (октава, мажор/мінор), решту (стиль, живий мікс, гітари, без публіки) перевіряє слух.
- [ ] Прибрати або замінити треки, що не пройшли; заповнити `notes.txt` (з'явиться в папці): 3–5 еталонів і «що копіювати».
- [ ] `run.bat check-tracks <папка> --demux`: стеми кожного треку в `<папка>\reference\<назва>\` (~1–2 хв на трек, потрібен GPU).
  Вони потрібні і шляху B (гітарна й барабанна доріжки), і UI як зразки.

## 3. Повне встановлення на новій машині (лише для ACE-Step; шлях B працює вже після `setup-all --main-only`)

1. Якщо взято ваги: покласти `ace-step\checkpoints` з флешки в `<MODELS_DIR>\ace-step\checkpoints`.
2. `run.bat setup-all` — доставить усе решту (~36 ГБ на піку разом із головним середовищем). Якщо зупиниться — зберегти
   останні 20 рядків виводу.
3. Папку пісні з флешки покласти де завгодно; `reference\` треків скопіювати в неї поруч з `orig\`.
4. Лише для генерації ACE-Step (UI її більше не має): перевірка режиму вивантаження через `tools\acestep_cover.py`
   (фрагмент 20–30 с, 1 варіант); очікується повідомлення про вивантаження: цей режим тепер у коді не підключений
   (був у колишньому UI), лишився виміряний у README.

Що **не перевірено** (перевіряється тільки на цільовій машині):
- повне встановлення на чистій системі (перевірено лише `--check`, закріплення версії ACE-Step, наявність закріплених
  версій пакетів для Python 3.11 і `torch 2.14.1+cu126`);
- карта з 8 ГБ відеопам'яті: режим економії перевірено лише симуляцією (баласт у відеопам'яті на карті 16 ГБ + жорстка стеля);
- Windows PowerShell 5.1 (вбудований у Windows 11): виправлення в `setup_all.ps1` не перевірено;
- фрагменти довші за 60 с у режимі вивантаження і обсяг оперативної пам'яті, потрібний для вивантаження;
- `check-tracks --demux` на десяти треках одразу (на восьми проходить, ~2 хв на трек із GPU 16 ГБ), `pack-data` на великих папках і `setup-all --main-only` на чистій системі
  (перевірено: `check-tracks` без `--demux` на одному файлі, `pack-data` на малій папці, `--check` і `check-tracks` у чистій копії репозиторію).

## 4. Шлях B (реальні семпли): прототип є, потрібна оцінка на слух

Прототип зроблено (опис і вимірювання: README): `run.bat ui` або `native-bank` + `native-arrange`. Далі:
- [ ] **Послухати й вирішити.** Спершу порівняння треків на одному фрагменті (UI: «Порівняти барабани / гітари всіх треків»
  або `native-arrange <корінь> --compare drums --start 40 --length 20`), потім повна пісня з обраних. Змішувати треки в один
  комплект не слід (перший прослуханий варіант «з усіх» вийшов кашею). З'ясувати: з яких треків брати барабани, з яких гітари; які семпли
  видалити з банку (UI: «Банк семплів»); чи не «машинно» звучить повтор; чи потрапляють гітари в акорди (блок «Що програма
  розуміє про пісню» дає корені акордів: хибні — це перша причина фальші). Без оцінки на слух нічого з наведеного не
  вважати покращенням.
- [ ] Якщо звучить близько: що чути як штучне, у порядку ймовірності: плоский малюнок гітари (три фіксовані візерунки), немає
  філів перед змінами розділів, бас оригінальний (електронний), немає акордів з терцією, лише одна гітарна партія.
- [ ] Відомі слабкі місця банку (виміряно на 8 треках): хетів мало в двох треках (3 та 2 із 10), креш лише з одного
  (критерій «хет, що дзвенить ≥ 0.9 с» суворий); акорди лише квінтові, 3–8 із 12 коренів на трек (разом покрито всі, A# і D#
  по 2–4 зрізи; решта зсувається на ≤ 3 півтони).
- [ ] Не перевірено: виконання на карті з 8 ГБ (гра семплами не потребує GPU, лише розділення на стеми), пісні з іншим
  розміром (не 4/4) або плаваючим темпом (сітка шукається як стала), пісня без вокалу.

Якщо шлях B не дасть бажаного, лишаються (не перевірено):
- **A. LoRA/LoKr для ACE-Step на зразках.** Модель вчиться всьому звуку, а не 30 с. За документацією репо:
  ~8 пісень ≈ 1 година на 12 ГБ, LoKr ≈ 5 хв (спробувати першим). Скрипта навчання в проєкті ще немає. Для карти з 8 ГБ
  навчання не перевірено; ймовірно, робити на карті з 16 ГБ. Перенавчання на 10 треках — припущення, не перевірене.
  Генерація ACE-Step з UI прибрана: для A знадобиться окремий скрипт виводу (CLI `tools\acestep_cover.py` лишився).
- **C. JASCO** (керування акордами й барабанним аудіо): немає в audiocraft 1.3.0, потрібна установка з Git; не перевірено.

## 5. Далі

- Метрики ритму/гармонії поруч із кожним результатом (лише підказка; `tools\compare_outputs.py` уже є).
- Для шляху B, за потреби після прослуховування: бас зі зразків замість електронного; філи й зупинки на межах розділів;
  ритм гітар із власного «іншого» шару пісні замість трьох фіксованих візерунків; терція в акордах (потрібен інший спосіб, ніж
  хрома спотвореної гітари); розділи за самоподібністю (зараз: співає чи ні, плюс гучність), а не лише за порогом гучності; гучність барабанів і баса за розділом
  взято грубо зі зразків (−3 / −1.4 / 0 дБ): уточнити на слух.
- `check-tracks` оцінює темп трекером ритму, який помиляється (приклад: 117 замість 175 для одного зі зразків; на пісні
  143.6 замість 145.95): замінити на `native_song.fit_grid` по стемах барабанів. Для шляху B темп зразків не критерій
  (удари й акорди зсуваються по висоті, але не по темпу), тож вердикт «≥ 5 треків на 130–155 BPM» стосується лише шляху A.
